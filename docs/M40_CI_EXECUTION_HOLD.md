# Temporary M40 workflow execution hold

These draft workflows intentionally fail without checking out code, installing tools, uploading artifacts, building, running a guest or publishing. This is a temporary safety hold, **not passing CI** and not release or boot approval. The failed checks intentionally do not supply test results. GitHub still provisions runners and initializes jobs; skipped or missing checks can be treated differently by branch-protection rules. Verify actual required checks independently. Existing runs, older heads, external processes and other workflow changes are outside this hold. Concurrency cancellation and trigger filters are unchanged.

The `alpine`, `desktop`, `stamp` and `build` jobs contain only a failing shell step. Build no longer depends on stamp during the hold, so stamp failure does not silently skip the architecture checks. The release job has an explicit false condition and only the failing step as defense in depth. Workflow token permissions are reduced to contents read. These changes are not a replacement for verifying GitHub's actual behavior.

The prior workflow contents at #63 head `3dacac1f5c2fd5b45f4ac63d66966daf0e13824c` remain in Git history; restore selectively only after independent review of bootstrap, fixtures, launcher, security controls and failure evidence. Do not treat the absence of new logs as a passing test. Restore uploads only with the reviewed test workflow, while keeping the full preexisting evidence.

The offline host checker verifies both held workflow files as exact text and checks their structural invariants and synthetic mutations. It is a drift alarm, not a GitHub interpreter or a security boundary, and cannot authorize CI dispatch, publishing or boot.

The separate `m40-host-controls.yml` workflow runs only the two synthetic strict-root host suites for PR #63's head. It checks out the PR head using a SHA-pinned action with read-only permissions and does not install packages or invoke QEMU. Checkout still uses network and GitHub-hosted infrastructure. These checks do not test a merge result, ISO, disk, CI guest or release. The workflow and tested code are PR-controlled and must be reviewed again on every head.

## What is sound

1. **Requests are appropriately scoped.** `alpine-udisks-smoke:26-39` requests
   Block.Device on `/block_devices/vda` and `/block_devices/vda1`, then
   Filesystem.MountPoints on that same vda1 object, via the well-known system-bus
   service `org.freedesktop.UDisks2`. This is not an ObjectManager text parser
   pretending to correlate unrelated strings. Unknown object/interface/property,
   access denial and transport errors stop the script before the success marker.
2. **Types and entire values are checked.** `udisks-property-check.py:17-29`
   requires one variant containing exactly a quoted NUL-terminated ay for Device,
   or a single-element aay for MountPoints. Fullmatch, fixed allowed identities
   and `re.escape` reject extra arguments, nested variants, wrong types, wrong
   devices, root substrings and record-injection attempts. ASCII decode and a
   64KiB read limit fail closed. Public UDisks documentation confirms Device is
   readable `ay` and MountPoints is readable `aay`; the latter is an array of
   mounted paths, empty if unmounted.[^https://storaged.org/doc/udisks2-api/latest/gdbus-org.freedesktop.UDisks2.Block.html][^https://storaged.org/doc/udisks2-api/latest/gdbus-org.freedesktop.UDisks2.Filesystem.html]
3. **Printer contract is plausible and independently checked.** Upstream
   `dbus-print-message.c::print_ay` emits printable ASCII followed by one NUL as
   `array of bytes "..." + \\0`; missing NUL omits that suffix and an embedded NUL
   selects hex output. `print_iter` emits `variant ` and an outer `array [...]`
   for aay, with recursive indentation. I inspected those paths and compiled
   only the exact extracted indent/print_hex/print_ay functions with a mock
   iterator, not DBus or GLib. Both fixed Device identities were accepted by the
   production helper; no-NUL, embedded-NUL and altered quoted values were
   rejected.[^https://raw.githubusercontent.com/d-bus/dbus/master/tools/dbus-print-message.c]
4. **No storage mutation or privileged rescue is introduced.** UID1000 is checked
   before creating the temporary directory or making a bus call. The only bus
   methods are the inherited GetManagedObjects and three Properties.Get calls.
   There is no Mount/Unmount/Format/Set, sudo/su fallback, policy change or retry.
   Temporary stdout files and their cleanup are ordinary local bookkeeping;
   “read-only” here correctly means no storage-configuration mutation, not zero
   filesystem writes or zero possible service activation.
5. **Original strict gates and deadlines remain.** All six original greps remain
   mandatory. The original enumeration still has a 30-second reply/40-second
   kill bound. Each additional readback has a 4-second reply/6-second kill bound,
   giving at most three extra bounded requests (18 seconds of kill bounds plus
   helper/shell overhead), not a relaxed enumeration deadline. Source inspection
   and command-mocked argument/order assertions establish this; the timeout mock
   does not itself prove real timer enforcement.

## Nonblocking risks and precise limits

- **Medium validation gap — actual signed guest printer remains unproven.** The
  helper intentionally rejects valid alternate printer encodings/versions that
  do not match its exact textual contract. The independent source inspection is
  upstream **master**, not the exact signed Alpine package implementation. Its
  timestamp/header variation is tolerated, but actual NUL representation,
  variant/aay formatting and the real UDisks root mount list still need a first
  guest observation. This is a CI acceptance prerequisite, not a reason to
  broaden matching or fall back to a weaker grep. No such guest evidence was
  generated by this review.
- **Intentional false-negative scope:** a legitimate vda1 mounted at both `/`
  and another path fails; alternate root device names, additional mount points,
  missing NUL or hex output also fail. That strictness is explicit in the code
  and README, and is appropriate only for the stated fixed virtio-root fixture,
  not a general disk browser.
- **Residual false-positive / claim boundary:** ObjectManager's Manager path and
  other original fragments are still global greps. This does not prove the
  Manager interface, a Partition interface/table relationship, size/UUID, actual
  kernel mount-table agreement or an atomic ObjectManager snapshot. Three good
  scoped properties cannot repair every malformed ObjectManager reply. Under a
  trusted genuine UDisks service on the named fixture they are materially
  stronger evidence; do not describe them as a complete disk/partition topology
  validator. The README already acknowledges several of these boundaries.
- **Low, expected transport trust:** header checking is only `method return `,
  not sender/serial validation. An independent direct-helper observation accepts
  arbitrary remainder text on that header if the body is exact. This is not a
  new acceptance bypass in normal use: genuine successful dbus-send supplies the
  header/body and binds the reply to its request. It does mean the helper must
  not be presented as standalone bus authentication or an arbitrary-log verifier.
- **No atomicity/owner pinning:** sequential readbacks can cross a service-owner,
  device or mount change. They prove separately observed properties, not one
  common instant/owner epoch. There is no hotplug monitor. Already documented.
- **Read cap is not an upstream output cap:** the helper reads at most 65537
  bytes, but dbus-send's earlier redirected output can grow until its command
  ends/is killed. The README states this accurately. Python startup/file parsing
  are not separately wrapped in a kill timer; this is not a total-script hard
  wall-clock cap.
